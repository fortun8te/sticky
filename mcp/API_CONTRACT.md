# Sticky MCP control contract

The MCP bridge talks only to the native app over loopback HTTP at:

```text
http://127.0.0.1:53318/api/v1/control
```

It never discovers peers, performs TLS pairing, reads peer certificates, or uploads directly to another device. The native app owns those operations. Every request includes the private `X-Sticky-Control-Token` generated by the native app; the bundled launcher reads it from Sticky's user-only application-support file.

## Endpoints

- `GET /api/v1/control/status` — local device (`id`, `name`, `platform`, `ver`).
- `GET /api/v1/control/peers` — discovered/paired peer array.
- `POST /api/v1/control/send` — enqueue a send. Body contains `kind`, optional `peerId`, `files`, or `text`; returns `{ transferId }`.
- `GET /api/v1/control/transfers` — transfer history/status array.
- `GET /api/v1/control/transfers/{uuid}` — one transfer record.
- `POST /api/v1/control/transfers/{uuid}/cancel` — cancel and return the updated record.
- `GET /api/v1/control/clipboard` — separate Sticky clipboard snapshot/history.
- `PUT /api/v1/control/clipboard` — replace the separate Sticky clipboard text.
- `GET /api/v1/control/errors` — user-visible errors.
- `DELETE /api/v1/control/errors` — clear errors and return `{ cleared }`.

Times are ISO 8601 strings or epoch milliseconds. Unknown optional fields may be present, but required fields above are stable. The bridge caps responses by default at 4 MiB and requests at 10 seconds.
